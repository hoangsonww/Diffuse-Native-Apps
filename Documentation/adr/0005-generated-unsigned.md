# ADR 0005: Generated Xcode project, unsigned CI

## Status

Accepted.

## Date

2026-08.

## Context

`.xcodeproj` is a merge-conflict magnet. Signing identities, team IDs, and provisioning profiles are personal or organizational secrets that do not belong in a public-product repository.

## Decision

- `project.yml` (XcodeGen) is the source of truth. `Diffuse.xcodeproj` is generated by `Scripts/bootstrap.sh` and gitignored.
- Build settings disable signing (`CODE_SIGNING_ALLOWED=NO`).
- CI produces unsigned archives/zips. Whoever ships the app signs outside this repository.
- No CodeQL or other hosted scanners that natter about style this repo does not use.

## Alternatives considered

- **Checked-in `.xcodeproj`.** Rejected: unreadable diffs, perpetual merge pain.
- **Signing in CI with a GitHub secret.** Rejected for a public repo that must stay clone-and-build; distribution is a separate act.
- **Tuist or Bazel.** Rejected: XcodeGen is enough; another graph tool is not.

## Consequences

- Contributors need XcodeGen.
- Widgets and app groups work fully only in signed local builds; unsigned widgets still compile and show empty/placeholder state.
- Release workflows upload artifacts and checksums, not App Store packages.
